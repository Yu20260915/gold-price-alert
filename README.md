# 金价提醒 · 云端检查（GitHub Actions）

电脑关机也能收到金价提醒。每 5 分钟在 GitHub 的云端服务器上检查一次行情，价格跨过设定的提醒线时，通过 Server酱推送微信。

## 它解决什么问题

| 场景 | 本机监控（gold-alert） | 本仓库（云端） |
|---|---|---|
| 电脑开着 | ✅ 每 60 秒，最及时 | ✅ 每 5 分钟（同时跑，互为备份） |
| 电脑关机 / 休眠 | ❌ 完全停止 | ✅ 照常推送 |

## 怎么改提醒线

直接编辑本仓库的 `thresholds.json`，改完点 **Commit changes** 保存，下一轮检查自动生效（一般 5 分钟内）。

```json
{
  "code": "XAU",        // 品种代码，别改
  "name": "国际金价",     // 推送里显示的名字
  "unit": "美元/盎司",    // 单位，别改
  "above": 4350,        // 涨破这个价就提醒，填 null = 不监控
  "below": 4260         // 跌破这个价就提醒，填 null = 不监控
}
```

- `resetGapPct`：复位容差（百分比）。价格触发后要回落到 `线 × (1 - 容差%)` 才算复位，复位后再跨线才会二次推送。默认 `0.3`，用来防止价格在提醒线附近来回震荡导致刷屏。

## 提醒行为

- **同一方向只推一次**：涨破推送后，价格必须先回到区间内，再涨破才会重新推。
- **休市不推**：行情时间超过 90 分钟视为休市，只记录不推送。
- **多源兜底**：优先东方财富，失败自动切新浪；国际金价还有 stooq 兜底。推送正文里会写明本次数据来源。

## 常用操作

| 想做什么 | 怎么做 |
|---|---|
| 看每 5 分钟的检查记录 | 仓库页 → **Actions** → 点最新的 run，看日志里的 `SUMMARY` 行 |
| 手动跑一次、验证微信通道 | **Actions** → 左侧 `gold-alert` → **Run workflow** → 勾上 `test_push` → 运行。微信会收到一条测试消息 |
| 暂停提醒 | **Actions** → 左侧 `gold-alert` → 右上 `⋯` → **Disable workflow** |
| 完全删除 | 仓库 **Settings** → 最下方 **Delete this repository** |

## 两个需要知道的限制

1. **GitHub 的定时任务是"尽力而为"**：高峰期可能延迟几分钟到十几分钟。它是兜底，不是秒级盯盘；秒级靠本机监控。
2. **仓库 60 天无活动会被自动暂停定时任务**。本仓库每天会自动提交一次 `heartbeat.log` 保活，正常情况下不会触发这个问题。

## 文件说明

| 文件 | 用途 |
|---|---|
| `check_gold.py` | 检查与推送主逻辑（仅用 Python 标准库，无第三方依赖） |
| `thresholds.json` | 提醒线配置，**你要改的就是这个** |
| `.github/workflows/gold-alert.yml` | 定时调度（每 5 分钟）+ 手动触发入口 |
| `state.json` | 跨线标记，由 Actions 缓存自动保留，**不用手动管** |
| `heartbeat.log` | 保活日期记录，自动提交 |

> 推送密钥（Server酱 SendKey）存在仓库的 **Settings → Secrets and variables → Actions** 里，名为 `SCT_KEY`。即使是公开仓库，Secrets 内容也不会公开显示。
